## Preparing a debug print reference

The [Kyoshi reference recipe](../centering-evidence/avatar-kyoshi-native-reference-specification.json)
uses the artwork mode on a transformed Magic face. Frozen
[photo observations](../centering-evidence/avatar-kyoshi-photo-observations.json)
separate the artwork rule from the adjacent title rule. All four now pass after
full-span support and alternate-proposal reacquisition. The
[The Ooze recipe](../centering-evidence/the-ooze-native-reference-specification.json)
also transfers successfully. The DEBUG supplied-artwork route now additionally
fits physical cuts from original-photo background contrast, retaining artwork
exactly. `CardCenteringPrintMatcher.$physicalRefinementEnabled.withValue(false)`
provides the unchanged-outer comparison control. Printed-reference and production
defaults are unchanged. Frozen physical points and full-span photo comparisons
are separate from design geometry; see the
[current receipt](../../docs/audits/centering-guided-repair.md#native-physical-cut-refinement-accepted--2026-11-07).

`build_print_reference.py` takes a full publisher image, its reviewed
`reference-only.json` specification, and a new output path. It verifies the
publisher image hash and stores the artwork rectangle, small contrast patches
and design identity. The output can be passed to the debug Centering screen
by its caller, or to the screenshot script via
`UI_CENTERING_PRINT_REFERENCE_SOURCE`. The FIN 289 test reference is in
[`PrintReferences`](../../TestFixtures/TradingCards/PrintReferences/fin-289.json).
Use `CenteringPrintPilotTests` for the source-photo accuracy and fallback checks.

Printed-frame specifications additionally use `kind: "printedBorder"`, a
`printedBorder` quad and an `artworkInterior` rectangle `[x0,y0,x1,y1]` selected
in the provider image. They retain `printing`, `sha256` and `displayedCut`.
The builder adds distinctive-artwork patches while preserving legacy artwork
preparation. The [Gengar fixture](../../TestFixtures/TradingCards/PrintReferences/gengar-151-094.json)
exercises the native printed-frame mode; it remains DEBUG and caller supplied.
The corpus test reads development entries only from the manifest and checks
unrelated-result equality. [Native pilot results](../../docs/audits/centering-guided-repair.md#native-printed-frame-pilot--2026-11-07).

The DEBUG screen also accepts `printReferences: [CardCenteringPrintReference]`,
or `-ui_debug_print_reference_library` with a JSON array file. It requires one
unambiguous recognized design; the explicit single-reference override takes
precedence. This supplies local references, not catalog retrieval. Library controls
and the 34-image sweep are in `CenteringPrintPilotTests`.

Provider specs can additionally opt into `includeFrameLandmarks: true` to select
up to two separated provider-image corner features per full-frame quadrant.
The [foil Gengar recipe](../centering-evidence/gengar-paf-native-reference-specification.json)
recovers identity but not a complete native measurement; existing recipes retain
their previous patch sets.

`track_card_paths.py --frame outer --physical-background --adaptive-sharp` is
an offline physical-edge hypothesis using consistent exterior contrast and only
observed image pixels. It rejects inconsistent polarity and cannot be combined
with a position prior or a non-RGB-mean signal. `--signal color_contrast` separately
tracks polarity-independent RGB gradient strength; existing local support and gap
limits still apply. Both are opt-in research methods, not app defaults. Squirtle
supports four physical sides but still rejects a complete printed frame; see
[current results](../../docs/audits/centering-guided-repair.md#foil-gengar-stop-and-squirtle-physical-edge-progress--2026-11-07).

`--dense-strips` samples the tangent at no more than one-pixel spacing, avoiding
sparse wide-strip sampling. It recovers supported Squirtle bottom coverage but
does not resolve the right gap. `color_region_probe.py IMAGE CANDIDATE_JSON
OUTPUT_JSON --side right` records a separate shared RGB transition model; its
synthetic control passes but real-photo support is insufficient, so it is stopped.
Neither diagnostic changes default scalar tracking or app measurement.

`track_card_paths.py --outward-polarity 1` restricts the scalar research search
to a brighter exterior when that polarity is defined by the reference feature,
such as a black artwork rule against silver. `-1` selects the opposite polarity.
It cannot override inferred physical-background polarity or RGB contrast. The
default still evaluates both polarities; this option is not chosen from ratios.

`measure_reference_candidate.py` optionally accepts `--fallback-candidate` for
independently observed photo paths from the same capture. It considers each alternate
only when primary support fails, retains coverage/gap criteria, and bounds it to
the existing reference search band. Accepted research geometry is not an accuracy
certification; physical-cut errors can still invalidate the ratio. See the
[current evidence](../../docs/audits/centering-guided-repair.md#reference-library-and-selective-venipede-repair--2026-11-07).

## Native annotation angle audit

each location once. The [PRE specification](../centering-evidence/pikachu-pre-native-reference-specification.json)

The [PRE receipt](../../docs/audits/centering-guided-repair.md#prismatic-foil-identity-and-unresolved-right-edge--2026-11-07)
records successful identity and a still-failing right-side accuracy check.

Current research stops and unfinished native transfer are recorded in the
[gold/shadow checkpoint](../../docs/audits/centering-guided-repair.md#shadow-stop-and-gold-pikachu-routing--2026-11-07).
`shadow_transition_probe.py` diagnoses cut/shadow identifiability at nine locations;
it never emits a complete measured frame. `register_print_reference.py --signal
gradientMagnitude` is an opt-in contrast-reversal diagnostic; default luminance
behavior is preserved. Neither alternative rescued the respective difficult photo.
`testGoldPikachuPrintedFrameResearchTransfer` now passes after the bounded native
strip-consensus change and source-crop correction of two foil-texture observations.
The three-design library sweep also passes; this remains a DEBUG supplied-library
route, not production acceptance. See the [latest native receipt](../../docs/audits/centering-guided-repair.md#native-gold-pikachu-transfer-accepted--2026-11-07).

The historical `gt_tool.py rederive` procedure selects an edge-wide profile
offset and translates the seed line. It does not independently measure that
line's angle. Its schema validation and repeated profile agreement therefore
cannot establish physical boundary identity or angle accuracy.

`edge_annotation_audit.py` instead fits individually observed native transition
points, retaining rejected samples, source hashes and an original-image overlay.
It uses no detector output and produces **review candidates only**, never new
ground truth. Yellow is the seed, cyan the fitted line, green retained points,
and red rejected points. Unsupported edges remain explicit failures. Boundary
identity must be adjudicated before adopting a candidate; a narrow residual
does not prove that it follows the right transition.

```sh
python3 -B review/centering-harness/edge_annotation_audit.py \
  TestFixtures/TradingCards/HEIC/IMG_0783.HEIC \
  TestFixtures/TradingCards/GroundTruth/IMG_0783.gt.json \
  /Volumes/T7/CodexBuilds/centering-annotation-review/new-unique-run
python3 -B -m unittest discover -s review/centering-harness \
  -p test_edge_annotation_audit.py -v
```

Requires Pillow, numpy, scipy, OpenCV and pillow-heif for HEIC. Use
`--geometry innerQuad --polarity either` to inspect an existing inner reference;
the default falling transition audits dark card cuts on light backgrounds.
These are explicit review assumptions, not universal detector defaults. The
output directory must be new so prior evidence cannot be overwritten.

## Bounded native research evaluator

`CenteringNativeResearchTests` is linked only into the test target. Select that
suite with `xcodebuild test -only-testing:TradingCardScannerTests/CenteringNativeResearchTests`
using the repository's usual scheme, simulator and external-SSD build paths.
Its development ablation uses only the ten already-exposed historical fixtures;
it never reads the sealed supplementary holdout. The full 36-setting experiment
is intentionally slower than production and must not be used as a production
latency result.

The xcresult contains one JSON attachment per input and `development-metrics-v1`.
Export the attachments with `xcrun xcresulttool export attachments --path <result>
--output-path <external-artifact-directory>`, then run:

```sh
python3 review/centering-harness/native_research_report.py <external-artifact-directory>
```

The summary preserves every configuration, unavailable ratios, abstentions,
per-axis median/p95/worst errors, and face/encasement subgroups. Two-native-pixel
line agreement is an evaluator diagnostic against the existing annotations; it
is neither the two-percentage-point ratio gate nor proof of physical identity.
The JSON retains annotation bands and ambiguity, input hashes, signed encoded
sRGB signal definitions, Gaussian scales, source line hypotheses, rejected fits,
supported positions and leave-one-band-out diagnostics. Process resident memory
and its lifetime peak are explicitly labeled; a bounded crop does not establish
a bounded decoder peak. See the
[current implementation/evidence ledger](../../docs/audits/centering-guided-repair.md).

`gt_tool.py` is the independent ground-truth tool. It contains no import of
the Swift analyzer and can validate the checked-in geometry or draw review
overlays from PNG/JPEG exports of the HEIC fixtures:

```sh
python3 review/centering-harness/gt_tool.py validate \
  TestFixtures/TradingCards/GroundTruth
python3 review/centering-harness/gt_tool.py overlay \
  /path/to/IMG_0347.jpg \
  TestFixtures/TradingCards/GroundTruth/IMG_0347.gt.json \
  review/centering-evidence/ground-truth/IMG_0347_gt.png
```

The overlay command uses the oriented image pixels and draws the physical-card
quad in red, the sleeve/encasement quad in amber, and the inner reference in
cyan. The JSON validator recomputes the rectified aspect and ratios directly
from the checked-in quads.

The review-only E4 probe can generate transition candidates without importing
the analyzer:

```sh
python3 review/centering-harness/gt_tool.py profile-candidates \
  <oriented-PNG-directory> \
  TestFixtures/TradingCards/GroundTruth \
  review/centering-evidence/diagnostics/E4
```

E4 candidates are not ground truth and must not be copied into the `*.gt.json`
records automatically. Multiple luminance transitions are possible on sleeve,
glare, and artwork edges; human adjudication is required before provenance can
be upgraded. The current records were produced later by the analyzer-free
`rederive` command, with a reviewed selection manifest and visual-silhouette
adjudication:

```sh
python3 review/centering-harness/gt_tool.py rederive \
  <oriented-PNG-directory> \
  <seed-ground-truth-directory> \
  <selection-manifest.json> \
  <output-directory> \
  --write-ground-truth
```

The current rederivation diagnostics and manifest are retained in
`review/centering-evidence/diagnostics/GT-rederived/`; the previous
five-pixel-grid records are archived under
`review/centering-evidence/ground-truth/provisional-2026-09-11/`.

## Exact-print registration controls

`register_print_reference.py REFERENCE PHOTO OUTPUT_DIR` records interior SIFT

preserving effective RANSAC tolerance. `reference_warp_control.py REGISTRATION_JSON

## Reference candidate gate

`reference_candidate_gate.py REGISTRATION_JSON CANDIDATE_DIRECTORY OUTPUT_JSON
--reference-top Y --width W` applies a coarse reference-position veto to supported

It never supplies projected coordinates as output. The current Clefairy control
rejects all combinations; see the [stopped veto](../../docs/audits/centering-guided-repair.md#reference-position-veto-stopped--2026-11-06).

`bash run_corpus.sh OUTPUT_DIRECTORY BOOTED_SIMULATOR_UDID` compiles a standalone
production analyzer with the native C pixel kernel. Supply an external-SSD output
directory. It checks source hashes and evaluates development entries only, in
both HEIC and PNG formats; the ten interim holdouts remain excluded. Existing
receipts are not overwritten. No annotation or supplied print reference enters
detection. `corpus_review.py RECEIPT_JSON IMAGE_DIRECTORY OUTPUT_DIRECTORY`
renders native overlays and contact sheets for visual identity triage, not accuracy
scoring. [Coverage receipt](../../docs/audits/centering-guided-repair.md#development-corpus-coverage--2026-11-06).

`outer_seeded_inner.py IMAGE BASELINE_JSON OUTPUT_DIRECTORY --fixture FIXTURE`
tests independent native side fits in a physical-perimeter-seeded shallow band.
It retains failures and does not emit a full frame or report ratios. The first
transfer experiment failed; do not promote it as a general replacement.

## Native photo review and combined path controls

`native_review_packet.py IMAGE WINDOWS_JSON OUTPUT_DIRECTORY` produces unmarked
native crops with coordinate ticks. Review windows locate crops, not boundaries.
`score_photo_bands.py BANDS_JSON PACKET_JSON CANDIDATE_JSON BASELINE_JSON OUTPUT_JSON`
compares frozen measurements with separately recorded visual intervals. All use
the central 50% paired span to avoid review extrapolation. Visual-band alternatives
are not calibrated confidence intervals or replacement ground truth.
`score_path_transfer.py ... --frame inner --side all` evaluates all four printed
paths together with the same five seed perturbations used for single-side work.
See [source-photo and back evidence](../../docs/audits/centering-guided-repair.md#source-photo-bands-and-back-transfer--2026-11-06).

## REQ-050 numerical sensitivity

`run_sensitivity.sh` compiles the analyzer with `DEBUG` observability and runs a
recorded numerical-parameter perturbation grid over every image in the supplied
fixture directory. The production 1200-pixel working cap remains fixed. The
grid is injected through `CardCenteringAnalyzer.NumericalParameters`, so the
production defaults are not edited for the experiment.

```sh
./run_sensitivity.sh
```

The harness writes `numerical-sensitivity.json` and
`numerical-sensitivity.md` to `artifacts/centering-sensitivity/` by default.
The JSON records the exact grid and per-fixture LR/TB mean, population σ, and
range, plus confident/declined/error counts. These are numerical-sensitivity
measurements only; they do not establish edge identity or accuracy.
