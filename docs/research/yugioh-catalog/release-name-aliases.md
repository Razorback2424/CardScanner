# Yu-Gi-Oh! release-name aliases

**Decision (2026-11-19):** A TCGplayer group and a YGOPRODeck `card_sets` set name refer to the same release when the open products agree on two things: the printed set code and the card. The two sides may still name the release differently. These aliases are recorded as reviewed data in `scripts/yugioh_correspondence_rules.json` under `setNameAliases`, and are generated by `scripts/reconcile_yugioh_release_names.py`.

## Why

Collectors identify a Yu-Gi-Oh! printing by the code printed on the card (for example `SDBE-EN001`), its rarity and its edition. The release name is only a label, and the two databases label releases differently:

| Pattern | TCGplayer group | YGOPRODeck set name |
| --- | --- | --- |
| Word order | Structure Deck: Machina Mayhem | Machina Mayhem Structure Deck |
| Spelled-out numbers | Champion Pack 1, Astral Pack 1 | Champion Pack: Game One, Astral Pack One |
| Reprint groups | Metal Raiders (25th Anniversary Edition), (Worldwide English) | Metal Raiders |
| Product suffixes | 2025 Mega-Pack, Legendary Collection 5D's | 2025 Mega-Pack Tin, Legendary Collection 5D's Mega Pack |
| Catch-all promo groups | Duelist League Promo, Miscellaneous Promotional Cards | Duelist League 13 participation cards, … |

The builder used to accept a source printing only when its set name exactly equalled the group name. So about 11,000 codes stayed `unreviewedCorrespondence`, even where code, card and rarity all agreed.

## Gates

An alias is proposed for a pair of TCGplayer group and code prefix, and only when all of the following hold:

1. Each open product in that scope has a resolved canonical card.
2. Its printed code appears in YGOPRODeck for that same card. A product without such a row is left open; it neither supports nor blocks the alias.
3. All supporting products share exactly one YGOPRODeck set name. If they disagree, or each product has two names, the scope is refused and written to the refusals file for review.

When the builder applies an alias, it checks:
- the exact group ID;
- the exact group name it was reviewed against, so a renamed group falls back to the exact-name rule;
- the code prefix, or the exact code for a code-level alias.

Rarity is still compared exactly, through the existing scoped rarity taxonomy. An alias grants no edition, artwork, price or automatic-scan authority.

## Groups that hold several sub-releases (2026-11-20)

Some TCGplayer groups hold several YGOPRODeck releases under one prefix: Duel Terminal 5a and 5b, Collectible Tin waves, Sneak Peek and Special Edition promos filed under the main set, Hobby League cards, and Shonen Jump issue promos. No single name then fits the whole prefix, and the scope used to be refused.

The reconciler now falls back to the printed code. Each code whose products agree on exactly one YGOPRODeck name gets an alias for that exact code only (`codes`, with an empty `codePrefixes`). The evidence rule is `printed-code-and-card-agree-per-code-v1`. A code whose products disagree stays open.

Result: 291 code-level aliases over 1,097 products. Refused scopes fell from 82 to 7, and the 293 prefix aliases were unchanged. Regenerating keeps an unchanged alias's original `reviewedAt`.

## Reprint groups

The 25th Anniversary and Worldwide English reprint groups share their printed codes with the original release. YGOPRODeck files all three under one set name. The alias therefore makes each reprint product correspond to the same source printing. Each one stays its own marketplace row, so a scan of `MRD-EN001` still offers all three, and the collector chooses. This follows the owner's principle: give the user more choice, without presenting a guess as a fact.

## What this does not change

`incompleteCodes` only withholds automatic scan selection. Automatic selection also needs a reviewed Konami release inventory (`yugioh_printing_inventories.json`). So aliases make the ledger honest, but they do not make scanning faster by themselves. The next lever is reviewed Konami release inventories for more releases.

## Gallery-backed English reference correspondence (2026-11-21)

The builder already retains English reference printings with photographed
edition evidence. Its correspondence census looked only at TCGplayer product
bindings, so a singleton reference could agree with YGOPRODeck in every field
and still produce a `printingCorrespondenceGap`.

The `reviewed-english-reference-gallery-v1` rule pins the gallery receipt as a
whole, including its reference-inventory hash and the exact group/code pairs
covered by the photographed specimens. The builder requires a sole existing
reference printing with edition support, one YGOPRODeck row in the capture,
and exact group, release title, code, canonical card ID, card name
and physical rarity. Short Print uses the existing Common physical-rarity
convention. A competing family member or multiple source assignments keeps the
code open. The rule leaves existing edition choices and automatic-scan gates
in place.
