## Recommendation and authority

Evolve the existing guided centering tool into an evidence-preserving measurement
workflow. Prioritize correct boundary identity, faithful geometry and useful
review before promoting native refinement or adding estimator families. Keep
the present automatic-reporting gate closed.

This follows the [product principles](../../README.md#three-principles): compute
what is knowable quickly, ask for the smallest missing human fact, and avoid
confident-looking guesses. Centering is a deliberate inspection task within
Collector Tools; it must not interrupt the high-throughput collection scanner.
The [commercial contract](CARDSCANNER_LAUNCH_MONETIZATION.md) already promises
guided estimation, explicit frame confirmation and annotated output, not a
predicted professional grade.

This document tracks the implementation sequence; it does not replace or weaken the
[centering contract](../../review/opus-card-centering-implementation-plan.md),
its §5.1 tolerances, REQ-040 holdout requirement or REQ-045 guided decision.
The [guided repair ledger](../audits/centering-guided-repair.md) remains the
implementation/evidence record. Older automatic-accuracy failures and newer
passing guided/UI tests describe different claims and must remain separate.

## Proposed implementation sequence

### 1. Freeze the baseline and preserve measurement meaning

**Implemented scope:** the analyzer retains independent inner lines; immutable
proposal geometry and detector confidence are separate from pending/user-confirmed
review. Small-angle detents preserve independent slopes. Positional variation
appears in the screen and export without changing headline aggregation, and
DEBUG receipts identify the ratio method and review provenance. Existing
one-action confirmation, live valid edits, explicit Square/Undo and invalidation
on invalid geometry, replacement input or photo rotation remain the user flow.
See the ledger for test and visual evidence; this is not automatic accuracy
acceptance. That first-slice receipt predates the full native input/candidate
provenance and boundary-identity types supplied by slice 2 below; it retains
existing input hashes, mapping, original proposal and source/binary identity.

Original first-slice plan: keep automatic reporting disabled, stop implicit
squaring of measured inner lines, and preserve proposal/edited/confirmed
provenance. Do not enable native refinement or change detector thresholds in
the same slice.

- Record branch, patch/source hashes, original-byte SHA-256, raw/oriented raster
  sizes, EXIF, color conversion, decode/downsample parameters, source path type,
  known lens/correction state, transform chain and algorithm version. Unknown
  capture history stays unknown. Hash before transformations.
- Run the existing centering selectors from the unchanged tree to establish a
  fresh baseline. Keep development-only benchmarks and their enablement explicit;
  reconcile selected methods against finalized result bundles.
- Retain raw proposals and independent line slopes. Make the existing Square
  action explicit and undoable; retain what it replaced. Audit auto-squaring and
  small-angle detents so ordinary nudges cannot silently erase independently
  adjusted geometry. Existing tests that deliberately specify squaring continue
  to test the explicit action; document the changed default behavior.
- Separate `reviewState` (pending/user-confirmed) from `boundaryIdentity`
  (supported/ambiguous/user-selected/unknown) and localization evidence. Preserve
  current valid-edit live updates, one confirmation for both frames, and
  invalid/new-input/rotation revocation. A user's choice is not ground truth.
- Add opposing-slope and rotated-print regressions: variation must survive
  analyze → model → editing → UI → export. Gate variation on sample ranges, not
  just mean tilt. Preserve the existing headline aggregation initially, with an
  explicit method label in diagnostic metadata.

**Exit:** guided safety, actual native Done/removal tests, undo/reset,
coordinate/render tests and the new geometry regressions pass; no stale result
or unexpected ratio change for the previously parallel fixtures. This slice
establishes faithful geometry, not new automatic perception accuracy.

### 2. Make reference identity and competing boundaries explicit

**Implemented — 2026-11-04.** Native candidate/input records, explicit reference
choice and side-only repair are covered by the
[slice 2 receipt](../audits/centering-guided-repair.md#reference-identity-and-competing-boundaries--2026-11-04).
Existing detector observations are retained; unavailable polarity/residual or
sampling data remain unknown. This does not promote new automatic perception.

Add small value types for an input record, boundary candidate, selected line,
reference definition, supporting sample bands, exclusions and selection reason.
Store original-native coordinates as the evidence authority; derive working,
display and rectified geometry through named transforms. Keep legacy scalar
projections derived rather than allowing two editable truths. Extract components
from the 5,369-line analyzer only as needed for these seams.

- Represent physical cut, sleeve/slab boundary, shadow, printed border,
  design-specific reference and unknown as distinct candidate roles.
- Replace blanket `artWindow` assumptions with reviewed reference definitions.
  An artwork box is not automatically a centered print reference; decorative
  asymmetry is not necessarily a cut/print defect. Reuse the existing registered
  Pokémon/Magic back path only within its demonstrated scope.
- Preserve candidates before selection, including their native line, signal,
  polarity, coverage, residuals and competing interpretations. Select semantic
  role before refining location. Do not select whichever ratio is closest to
  50/50, or independently align a template to the printed frame and thereby
  remove its displacement.
- For unsupported designs, offer a deliberate user-selected reference or no
  measurement. A default inner rectangle remains an unverified placement aid.
  Manual selection may produce a clearly labeled geometric estimate; it cannot
  establish grading-reference equivalence.

**Exit:** cut/shadow and printed-border/artwork fixtures preserve both candidates
with reasons; absent references remain unavailable; a single side choice resolves
only that ambiguity and does not silently replace the other seven boundaries.

### 3. Evaluate a bounded coarse-to-native refinement pipeline

**Research evaluated — 2026-11-04; promotion blocked by accuracy and REQ-040.**
The test-target evaluator records all 36 configurations over ten development
images, with bounded crops, explicit sRGB signals, robust tracks, band stability,
revision cancellation/cache, process-memory observations and separate recall,
selection, abstention and ratio-error metrics. The
[slice 3 receipt](../audits/centering-guided-repair.md#bounded-native-research-evaluation--2026-11-04)
records 92 passes/one expected skip and the failed accuracy exit. No production
perception change, decoder-memory guarantee or holdout acceptance follows.
Further signal/aggregation families are deferred until they address a specific
role-identification failure. Independent guided slices 4–5 are recorded below.

Keep the current 1200-pixel proposal pass and native-coordinate mapping. Use
native strips only around credible candidate lines; reuse/cancel work by input
and geometry revision. Retain the original compressed bytes and bounded crops.
Instrument actual decode peak memory: a crop-size limit does not itself prove
the image decoder never materializes a full raster. The synchronous native-detail
crop also needs interaction profiling before extending its workload.

In research mode, compare weighted brightness, arithmetic RGB mean, RGB chroma,
selected channel differences and signed gradients at several scales. Start with
the attachment's settings as one recorded experiment. Add profile alignment,
half-contrast/derivative estimates, median and trimmed aggregation only when the
ablation answers a specific failure. Preserve signal units and color-space
definitions; fixed thresholds do not generalize by declaration.

Fit supported straight segments with robust residual rejection or a bounded
Huber/soft-L1 fit. Exclude corners/glare/occlusion, retain spatial coverage and
leave-one-band-out variation, then intersect supporting lines for virtual
corners. Keep independent inner slopes. Compare candidate recall separately from
selection error and local-fit error. If the right boundary is not proposed,
widen/rethink its semantic search instead of relaxing fit thresholds.

Do not promote V2b as it stands. Filters of one photograph are correlated;
agreement cannot authorize a shadow edge. A small classical Swift/C implementation
fits the current app; OpenCV can serve as an offline transform comparator, but
adding it as an iOS dependency needs measured benefit. A trained model is a later
option only if labeled data demonstrates that classical role identification is
the binding limit and the existing latency budget can be met.

**Prerequisite:** freeze the final diverse holdout required by REQ-040 before
any production perception change. **Exit:** development ablations improve
role-correct candidate recall and ratio error without hiding regressions in
abstentions, and retain ambiguity when interpretations remain plausible.

### 4. Add explicit spatial measurement and sensitivity

**Implemented and tested — 2026-11-04.** The
[slice 4 receipt](../audits/centering-guided-repair.md#spatial-measurement-and-explicit-sensitivity--2026-11-04)
records the prespecified common-row/column diagnostic, independent scenario
ranges, interior-grid validation and 192 passes/one expected skip. The existing
headline convention and production perception are unchanged. Presentation of
these diagnostics is recorded in slice 5 below; numerical passes do not close physical
accuracy or REQ-040.

Use one homography from the selected physical cut. Transform all printed lines
through it, never normalize the printed frame independently. A read-only rectified
review is useful; retain the original-image overlay as the traceable source.
The distinction between a point transform and resampling a raster is documented
by [OpenCV's transform API](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html).
Homography assumes planar geometry; lens distortion and bowing require separate
evidence, as described in [OpenCV's homography guide](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html).

- In card-oriented, top-left-origin rectified coordinates, intersect inner and
  outer lines at the same valid row for LR and the same valid column for TB.
  Define sample positions and supported bands before evaluating outcomes.
  Compute `100 × L/(L+R)` and `100 × T/(T+B)`; reject absent/nonpositive margins.
- Record per-position ratios, margin variation, side slopes and coverage.
  Compare midpoint and a prespecified robust aggregate with the legacy endpoint
  mean on analytical fixtures. Adopt a new headline convention only as an
  explicit, versioned contract amendment; never silently change expected values
  to make tests pass.
- Add real forward→inverse checks on an interior grid. Test physical fit using
  supported image points/held-out edge bands, not just four fitted corners.
  Do not force a standard aspect ratio as an accuracy repair: coordinate scaling
  on an axis cancels in its ratio, and a plausible aspect does not prove identity.
- Recompute the complete homography and both-axis measurements under plausible
  outer/inner line alternatives. Keep semantic alternatives separate from local
  perturbations around a selected line. Do not combine individually impossible
  edge choices into a purported physical scenario.
- Report a boundary-choice sensitivity range with stated assumptions, distinct
  from spatial variation. Block-bootstrap and JPEG/blur perturbation experiments
  belong in the evaluator first; conditional variability is not a calibrated
  confidence interval. If no defensible bounds exist, say uncertainty is unknown.
- Invalidate all derived ranges/overlays/export snapshots after edits, reset,
  rotation and new input. Preserve immutable original-proposal evidence with its
  own revision so it is never labeled as evidence for later manual lines.

For scale: with two 25-pixel borders, changing one to 26 changes 50/50 to
50.98/49.02, about 0.98 pp. Opposing ±1-pixel changes can produce 52/48. A
four-pixel increase to only the bottom margin yields 46.30/53.70. These are
arithmetic sensitivity examples, not inferred Gengar error bars. Subpixel
controls improve placement granularity; extra decimals create no image detail.

**Exit:** all supported transforms preserve known geometry within existing
tolerances; a synthetic cut/shadow pair 4–5 native pixels apart produces separate
reviewable scenarios and a changed full-pipeline range, not a forced choice.

that side with two selectable lines and an enlarged original-pixel region.
Avoid an eight-edge wizard or a dashboard of thresholds. Advanced diagnostics

Add an optional rectified comparison and show support/exclusion bands only while
reviewing the relevant edge. Reports should distinguish user-confirmed estimates,
selected reference, spatial variation and sensitivity. Original and rectified
diagnostic overlays should retain candidate alternatives and excluded regions;
the default share remains an understandable original-image result.

Changing the report's contents and adding a rectified inspection surface extends
