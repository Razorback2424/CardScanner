# Five-game Browse filter and sort plan

**Status** · Implementation committed to `main` as `e970ef63` on November 21, 2026. Investigation baseline `a1dde0b9`; physical-device and UI acceptance remain open.

In Browse → **any game** → Cards, users should be able to choose a filter and a sort in either order. With the same catalog, ownership, and quote snapshot, both sequences should produce the same cards in the same order. The starting acceptance case is Magic → Chocobo Track Foil → Price High to Low, with the price for the matching foil visible on each priced tile.

## What caused the reported behavior

- **Game-wide Browse had no sort selection.** The screen offered Filter and Sets. With an empty query it walked sets newest-first. With search text it appended provider or adapter pages. Both paths called the shared grid without a price map, so the grid showed blank prices. [Browse view](../../TradingCardScanner/Views/BrowseView.swift)
- **A treatment by itself triggered no quote lookup.** A price-range filter requested quotes, but the view discarded those price resolutions and the pending rows. The pager checked finish eligibility and then priced the original summary, which could use another finish’s quote on an unqualified printing. Magic set pages already retained a price sidecar and the service could resolve an explicit finish. [Filters and pager](../../TradingCardScanner/Models/CatalogBrowseFilters.swift) · [Browse service](../../TradingCardScanner/Services/BrowseCatalog.swift)
- **Inside a set, some of this already worked.** The set grid combined text search, ownership and price or collector-number sort. It showed prices and offered “Sort Entire Set” when a price sort covered only loaded pages. The Sets directory had its own ordering. Root Browse search interleaved card and sealed results by relevance. [Browse view](../../TradingCardScanner/Views/BrowseView.swift) · [Set presentation](../../TradingCardScanner/Services/CatalogSetPresentation.swift)
- The screenshot shows Chocobo Track Foil on Forest FIC 482 and Mountain FIC 481. The view path explains blank prices even when a provider has a quote. The existing Chocobo regression covers treatment matching on Traveling Chocobo FIN 568. Add the screenshot printings to the fixture and check their current provider quotes during validation. [Existing Browse regression](../../TradingCardScannerTests/BrowseFeatureTests.swift)

## Controls and ordering

Place a labeled **Sort** menu in the results header beside the active filters, with the current choice visible. Keep the existing filter sheet, removable chips and Sets navigation. Offer **Recommended** as the default (current browse order or search relevance), **Price High to Low**, **Price Low to High**, **Release Newest First**, **Release Oldest First**, and **Name A–Z / Z–A**. Keep collector-number directions inside a set. Label the date as **Release** so its meaning is clear in a catalog.

Keep query text, filters and sort as independent fields in the screen’s query state. Changing one reapplies the others. Clearing filters preserves sort, and selecting Recommended preserves filters. Retain card state when opening details or switching to Sealed and back. Keep each game’s selection scoped to that game during the Browse session. Show the selected sort and filters even on empty or loading results, with actions to clear filters or retry when relevant.

Date sorts use an authoritative printing release date, with an authoritative set release date as a labeled fallback. Unknown release dates and unavailable prices sort after known values in both directions. Break ties using set identity, natural collector number and stable printing/finish identity. If a tile groups several eligible finishes, rank it by its highest eligible usable USD quote in either direction and label which finish the amount represents. Keep individual finish prices on their respective chips. When a price range is active, remove failing finishes before choosing the representative. Use the displayed amount to rank the tile.

## Implementation and follow-up

Game-wide Cards, set detail, root search and sealed product grids now expose sort controls in their respective scopes. The Cards grids share exact-finish quote and ranking rules. Game Browse keeps query state per game, with independent card and sealed search text. Full-scope sorting uses complete local set snapshots where available and an explicit, cancellable page traversal elsewhere. Broad Magic scopes still rely on paged Scryfall results. A dedicated bulk price index remains a scalability follow-up, along with provider latency and physical-device acceptance.

### Design requirements

1. **Fix tile prices and price filters.** Resolve cheap predicates first, expand eligible finishes, and retain each candidate and quote state by stable identity. Use one projection for price-range checks, the tile or chip amount, VoiceOver and ordering. Reuse `OwnedCatalogPrice` for exact owned rows, including its unpriced-owned behavior. Carry currency, source and actual quote age, plus distinct pending, stale, confirmed no USD quote, mapping pending, printing review and retryable failure states. Show cached valid amounts immediately, identify stale amounts and keep pending range checks retryable after pagination advances. Price deduplicated visible and near-visible matches in bounded batches even with Recommended selected. Browse price reads follow the existing save and history authority. [Owned price policy](../../TradingCardScanner/Services/OwnedCatalogPrice.swift) · [Pricing correctness contract](pricing_correctness_and_coverage.md)
2. **Add shared controls and pagination.** Rank filtered candidates before paginating where the full scope is available. Run filtering and ranking off the main actor. Reuse set-screen coverage and retry patterns. For incomplete sources, show “Sorting X loaded matches” with progress or a way to complete the scope. Track catalog traversal and quote coverage independently. Batch reorder updates and preserve the visible scroll anchor while prices arrive. Key work to game, scope, query, filters and catalog authority, plus ownership revision where applicable. Reuse candidates and valid quotes on direction changes. Cancel superseded work and reject delayed responses.
3. **Complete full-scope ranking across all five games.** Use the existing checklist and adapter indexes to rank local results before emitting pages. For broad Magic queries, use provider ordering only where its semantics match the selected filters and displayed price. Otherwise use an index of summaries and quotes populated from approved bulk data and tied to the active catalog generation. Broad game-wide and cross-game price ranking needs bounded bulk/group reads or a versioned price index. Keep artwork lazy and reuse request pacing, caching and negative-result policy. When a network-backed scope cannot be completed, show partial coverage and offer retry or narrowing by set. [Scryfall bulk and rate-limit guidance](https://scryfall.com/docs/faqs/i-m-having-trouble-accessing-the-scryfall-api-or-i-m-blocked-17)
4. **Extend to adjacent Browse surfaces.** Reuse the query and presentation behavior inside sets, preserving checklist completion. In root search, add game and content-type filters and offer price and release sorts within the selected Cards or Sealed scope. For supported Sealed lanes, use separate query state, exact product/variant quotes, and product release dates when available or vendor set dates as a labeled fallback. The sealed product summary currently carries quote timestamps and the sealed set summary carries release dates. Runtime capabilities govern availability. [Sealed Browse](../../TradingCardScanner/Views/SealedBrowseViews.swift) · [Sealed summary models](../../TradingCardScanner/Models/JustTCGMarketModels.swift)

## Verification and rollout

On November 21, 2026, the working tree based on `a1dde0b9` passed 295 focused
`TradingCardScanner-ProfileLocal` tests on an iOS 27.0 iPhone simulator, with
8 skips and zero failures. Coverage included rendered pagination, set
presentation parity, Chocobo Track Foil quote selection, exact One Piece
finish pricing, Pokémon, Lorcana and Yu-Gi-Oh! pricing, and sealed Browse.
Live quotes for the screenshot and physical-device acceptance remain open.

- **Deterministic tests.** For each game, apply filter → sort and sort → filter and compare ordered IDs and visible amounts on the same snapshot. Cover empty and typed queries, price range with finish, treatment, edition or ownership, both directions, ties, unknowns, and filter/sort resets. Include a later-page result that outranks page one, duplicate and failed cursors, a price retry after advancing the cursor, stale and non-USD quotes, owned-price precedence, and late results after a query, game, ownership or catalog change.
- **Simulator.** Use `TradingCardScanner-ProfileLocal` with focused `BrowseFilterTests`, `BrowseLoadingRefinementTests`, `BrowsePresentationTests`, `BrowsePaginationRenderTests` and affected game pricing suites. Verify compact iPhone, iPad split view, large Dynamic Type, VoiceOver, and navigating into a tile and back. Put DerivedData and test artifacts on the external SSD when available.
- **Provider and device acceptance.** Check live exact-printing quote coverage for the screenshot and representative mapped, unmapped and ambiguous cases in each game. Record time to first grid, first price and complete ordering, plus request count and memory against a baseline. Include cold and warm starts, a broad Magic sort and a large Pokémon set, offline and slow connections, and Low Power Mode. Require stable full-scope results where supported, accurate partial coverage elsewhere, and bounded provider request counts. Use one actionable status for partial coverage or a retry, with a plain-language explanation when a price is unavailable.
